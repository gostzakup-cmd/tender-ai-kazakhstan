# Tender AI Kazakhstan

MVP для Google Apps Script V8 + Google Sheets, без Python, сервера и
сторонних библиотек. Поиск поставщиков и расчёт прибыли не включены.
Существующие `.gs` сохранены и доработаны; добавлен `V3.gs`.
`appsscript.json` сохранён.

**Адаптер написан по официальной схеме V3. Установка и диагностика готовы;
боевой запуск требует проверки ответа с вашим токеном.** Поля суммы и
количества лота подтверждены: `Lots.amount` и `Lots.count`. Сумма пункта
плана или объявления не используется. Полный ежедневный охват страны
пока не проверен на реальных данных и квотах Google.

[Источники и маппинг](docs/API_VERIFICATION.md) ·
[Реализация и блокеры](docs/MVP_STATUS.md) ·
[Результаты проверок](docs/TEST_RESULTS.md).

Для уже созданного проекта доступна [загрузка через clasp без ручного
копирования](docs/APPS_SCRIPT_UPLOAD.md): резервная копия, сохранение
посторонних файлов и проверка повторным чтением. В облачной среде
Google OAuth отсутствует, поэтому удалённая загрузка пока не выполнена.

Подготовлена [публикация через GitHub Actions](docs/GITHUB_ACTIONS.md)
для `gostzakup-cmd/tender-ai-kazakhstan`: только ручной запуск,
зашифрованные резервные копии, отдельная проверка плана и повторное
чтение после загрузки. Workflow пока не запускался.

## Установка и первая диагностика

1. Создайте Google-таблицу или откройте ранее созданную таблицу проекта.
   Откройте **Расширения → Apps Script**. Развёртывать веб-приложение не нужно.
2. Создайте/обновите семь файлов типа «Скрипт»: `Config`, `Sheets`, `Api`,
   `V3`, `Sync`, `Diagnostics`, `SelfTests`. Скопируйте одноимённые `.gs`
   из репозитория, сохраняя имена. Папки `docs` и `tests` копировать не нужно.
3. В **Настройках проекта** включите отображение `appsscript.json` и
   скопируйте манифест из репозитория. Он использует V8 и Asia/Almaty.
4. Сохраните проект и выполните `setupTenderMvp`. Подтвердите разрешения
   Google на таблицы, HTTP-запросы и триггеры. Появятся ALL_LOTS, NEW_TODAY,
   ACTIVE_LOTS, SETTINGS, LOGS. Повторная настройка сохраняет данные и
   DAILY_HOUR; несовместимые заголовки не перезаписывает.
5. Выполните `runTenderSelfTests`. Ожидается `passed: 12`, `total: 12`,
   `apiTested: false`. Проверка не обращается к API и не изменяет листы.
6. **Настройки проекта → Свойства скрипта / Script Properties**:
   добавьте `GOSZAKUP_TOKEN` со своим токеном без `Bearer` и переводов строк.
   Токен не помещайте в исходники, SETTINGS или чат. Старое имя
   `GOSZAKUP_API_TOKEN` поддерживается для совместимости; новое имеет приоритет.
7. Выполните `testGoszakupV3Connection`. Endpoint уже задан:
   `https://ows.goszakup.gov.kz/v3/graphql`, POST JSON + Bearer.
   Функция проверит introspection схемы и до двух страниц Lots. Листы
   лотов, состояние обхода и триггеры остаются без изменений; отчёт —
   в LOGS (`API_V3_DIAGNOSTIC`) и журнале выполнения.
8. Выполните `inspectGoszakupStatusReference`. Это документированный
   `GET /v3/refs/ref_lots_status`; отчёт покажет реальные коды/названия и
   полноту справочника, не назначая активность наугад.
9. Выполните `exportTenderApiDiagnostic` и передайте **только его отчёт и
   отчёт справочника**, без токена. Строковые образцы ограничены и
   отражённое значение токена удаляется. Если отчёт слишком большой для
   Script Properties, скопируйте событие `API_V3_DIAGNOSTIC` из LOGS.

Для первой диагностики достаточно токена. Ожидается `schemaVerified: true`
при совпадении реальной схемы и `mvpReady: false`, пока не подтверждены
три настройки ниже. Образцы содержат выбранные реальные поля и позволяют
проверить маппинг. Если сервер не вернул документированный pageInfo,
получите `V3_PAGE_INFO_UNVERIFIED`; это не считается концом реестра.

## Настройки перед синхронизацией

Добавляются в **Script Properties** после проверки официальных данных.

| Имя | Какое значение необходимо |
| --- | --- |
| GOSZAKUP_API_DATE_TIMEZONE | Подтверждённый часовой пояс дат API без смещения, в формате IANA. Asia/Almaty в манифесте задаёт часы приложения, но не доказывает зону строк API |
| GOSZAKUP_LOT_URL_TEMPLATE | Проверенная ссылка на отдельный лот на HTTPS goszakup.gov.kz, www или old; заменяемые параметры `{id}` и при необходимости `{trdBuyId}`. `{id}` обязателен; URL объявления не заменяет ссылку лота |
| GOSZAKUP_ACTIVE_STATUS_CODES | JSON-массив реальных `RefLotsStatus.code`, допускающих подачу заявок. Нужны все применимые способы закупок; один пример статуса не обеспечивает полноту |
| GOSZAKUP_PAGE_SIZE | Необязательно: целое 1–200, по умолчанию 100 |
| GOSZAKUP_V3_ENDPOINT | Необязательно: официальный endpoint уже установлен; разрешён только HTTPS на ows.goszakup.gov.kz |
| GOSZAKUP_V3_FIELD_MAP | Необязательно: JSON-объект изменений внутренних назначений → реальных GraphQL-путей. Исходный маппинг приведён в V3.gs и API_VERIFICATION.md; выдуманные пути не допускаются |

Сейчас отсутствующие zone/URL/status не заменяются предполагаемыми
значениями. Публичный портал показывает лоты через модальные окна;
устойчивый адрес конкретного лота пока не подтверждён. По реальному
отчёту следует завершить эти настройки и при необходимости поправить
сопоставление полей. Деньги и количество запрещено сопоставлять с
вложенными полями Plans или TrdBuy даже через настройку FIELD_MAP.

После настройки:

1. Повторите `testGoszakupV3Connection`. Требуется `mvpReady: true`:
   совпала схема, проверена пагинация, есть подходящий нормализованный
   образец, нет ошибок. Изменение конфигурации требует повторной проверки.
   Две страницы не подтверждают полный охват страны.
2. Выполните `syncTenderLots`. Дождитесь `SYNC_COMPLETE` в LOGS.
   Продолжения выполняются автоматически; SYNC_PAUSED — сохранённый курсор,
   а не окончание обхода. SYNC_FAILED требует устранения указанной причины.
3. Сверьте сумму/количество, номера, даты и ссылки с порталом. Повторите
   синхронизацию: ID не должны дублироваться, изменения должны обновляться.
4. В SETTINGS задайте DAILY_HOUR, целое 0–23 (по умолчанию 7).
   Выполните `installDailyTrigger`: останется один ежедневный триггер
   dailyTenderSync по Asia/Almaty. Google выбирает минуту внутри часа.
5. Проверьте следующее автоматическое выполнение, его длительность,
   число страниц и отсутствие квотных ошибок. Только этот прогон покажет,
   успевает ли текущая стратегия собирать данные каждый день.

После перезагрузки таблицы доступно меню **Tender AI Kazakhstan**.
`showTenderStatus` показывает наличие токена, готовность, сохранённые
страницы и триггеры. `removeTenderTriggers` удаляет только триггеры проекта,
сохраняя данные и курсор. Старый `testGoszakupConnection` оставлен для
диагностики legacy REST `/lots`, ежедневный сбор использует V3.

## Данные и обновления

| Лист | Назначение |
| --- | --- |
| ALL_LOTS | Уникальные товарные лоты с суммой одного лота ≤ 10 000 000 KZT, включая завершённые |
| NEW_TODAY | Подходящие лоты, опубликованные сегодня по Asia/Almaty |
| ACTIVE_LOTS | Лоты с разрешающим подачу кодом статуса и открытым интервалом подачи |
| SETTINGS | DAILY_HOUR и справочные параметры приложения; без токена |
| LOGS | Настройка, диагностика, начало/пауза/завершение обхода, ошибки и триггеры |

Колонки: ID, номер закупки (объявления), номер лота, название, количество,
сумма KZT, заказчик, БИН, публикация, начало/конец подачи, статус, ссылка,
первое обнаружение, последнее обновление и признак активного статуса.
NEW_TODAY использует публикацию объявления, а не первое обнаружение.
Повторные сроки подачи имеют приоритет, если возвращены обе даты.

Полный обход Query.Lots учитывает изменения старых записей. Товарный
тип определяется по всем связанным Plans.refSubjectTypeId с проверкой
покрытия pointList; код 1 документирован как «Товар». Сумма/количество
читаются прямо из Lots. Подтверждённые удалённые, нетоварные или ставшие
дороже 10 млн записи удаляются из ALL_LOTS. Исчезновение записи из выдачи
не считается доказательством удаления. Некорректная страница останавливает
обход до записи, вместо молчаливого пропуска непроверенных данных.

Обход использует limit/after и документированный extensions.pageInfo:
hasNextPage=false завершает обход; true продолжает по lastId, включая
короткую или пустую промежуточную страницу. ID проверяются на повторы и
изменение порядка. Данные записываются и flush выполняется до сохранения
курсора; повтор страницы обновляет существующий ID. ALL_LOTS сохраняет
физические позиции строк; удалённые остаются пустыми. БИН/ID хранятся
как текст, внешние названия защищены от исполнения формул.

## Ошибки и ограничения

| Событие | Действие |
| --- | --- |
| API_TOKEN_MISSING | Добавить GOSZAKUP_TOKEN в Script Properties |
| API_PROXY_CONNECT_403 | Прокси отказал в HTTPS-туннеле до API; проверить сетевой маршрут/домены. Это не доказательство неверного токена |
| API_HTTP_401 / API_HTTP_403 | Получен HTTP-ответ сервиса/шлюза; проверить авторизацию, права и маршрут |
| API_GRAPHQL_ERRORS | HTTP 200 с GraphQL errors не является успешной страницей |
| API_V3_SCHEMA_MISMATCH / API_V3_RESPONSE_FIELD_MISSING | Реальная схема/ответ отличается: проверить официальный контракт и безопасный отчёт |
| API_V3_PAGE_INFO_MISSING / API_V3_PAGE_INFO_INVALID / API_V3_PAGINATION_ORDER | Полнота обхода не подтверждена; исправить контракт пагинации по реальным данным |
| API_V3_CONFIGURATION_REQUIRED | Задать подтверждённые zone/URL/status |
| API_V3_LIVE_CHECK_REQUIRED | Повторить диагностику после изменения настроек |
| API_HTTP_429 / API_RATE_LIMIT | Подождать по Retry-After; продолжение сохраняет курсор |

429/5xx и временные сетевые ошибки повторяются до четырёх попыток.
Длинный Retry-After переносит продолжение. После примерно трёх минут
скрипт сохраняет состояние и планирует продолжение через минуту;
страховочный триггер помогает после жёсткого завершения Google. После
трёх неудачных продолжений автоматика останавливается до ручного или
ежедневного запуска. Одновременные исполнения блокируются.

**Масштаб остаётся блокером проверки:** сканируется весь реестр, чтобы
обновлять старые лоты. Квоты URL Fetch/исполнений/триггеров и предел Sheets
10 млн ячеек могут не позволить завершить обход за сутки. На каждой
странице читается и записывается накопленная таблица. Если обход длится
дольше суток, ежедневный запуск продолжает его и не гарантирует сбор всех
новых лотов за каждый день. Инкрементальная стратегия по документированным
indexDate/lastUpdateDate пока не внедрена: нужно проверить реальные
фильтры, порядок и распространение изменений связанных объектов.
Sheets не является транзакционной БД; не редактируйте строки во время обхода.

LOGS не содержит токен, заголовки авторизации или сырые тела ошибок.
Редакторы Apps Script могут читать Script Properties — выдавайте доступ
к проекту только доверенным людям.

## Проверки в облачной среде

Применён skill cloud-environment-onboarding:setup. Официальные страницы
V3 теперь доступны; прежний CONNECT 403 не трактуется как ошибка токена.
Сетевая настройка облачной среды не управляет сетью Apps Script.

```sh
cd /workspace/tender-ai-kazakhstan
node --test tests/core.test.cjs
```

Пройдены 63 локальных теста, включая 12 self-tests в модели Google.
Node нужен только для проверки JavaScript, сервером приложения не является.
Для тестов ядра npm-зависимости не нужны. Инструменты GitHub Actions
имеют отдельный lockfile в tools/ci; порядок проверок — GITHUB_ACTIONS.md.
Реальные Google-
разрешения, авторизованный полный обход и daily run здесь не выполнены.
