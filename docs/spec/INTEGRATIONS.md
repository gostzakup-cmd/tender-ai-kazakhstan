# Реальные интеграции, разрешения, стоимость и ограничения

Это варианты будущих адаптеров через **UrlFetchApp JavaScript**. Никакого
собственного сервера, Python, фиктивного интернет-поиска или mock AI в продукте.
Проверены публичные документации, но платные вызовы и авторизованный поиск
не выполнялись. [sources.json](sources.json) содержит HTTP-статусы, SHA-256,
дату и URL. Тарифы проверяются повторно перед выбором/оплатой; квоты и
налоги зависят от аккаунта/региона. Цены сервисов не являются ценами товара.

Все новые OAuth scopes и IAM будут внесены только отдельными PR с
обоснованием и повторной авторизацией. В текущем manifest Drive/cloud-platform
нет; этот PR их не добавляет. Существующая защита Actions от непроверенного
изменения scopes, backup и чтение после upload сохраняются. Указать scope
в плане не значит, что он уже авторизован или что owner имеет роль IAM.

Возможная более простая альтернатива — Gemini Developer API (AI Studio) с
API key вместо Vertex. Он действительно читает PDF (документация указывает
до 50 MB/1000 страниц для PDF, контекст модели также ограничивает запрос).
Это **не гарантия** полного извлечения или точных цитат. Сравнить условия
использования/хранения данных free/paid и выбрать владельцем. Не включать
одновременно два AI-провайдера «на всякий случай» и не передавать ключи в чат.

## Что не является достаточной реализацией

- Drive import PDF→Google Docs/OCR поддерживается Google, но часто теряет
  точные страницы/таблицы/чертежи. Его можно испытать как дешёвый fallback,
  но не объявлять полной ТС и точной ссылкой на страницу без проверки.
- Gemini PDF native понимание само по себе не доказывает все требования.
  Нужны page coverage, проверка quote/anchor, критический veto и golden set.
- Search snippets, LLM memory/grounding-summary и «похожие товары» не являются
  подтверждёнными SKU, ценой, наличием или коммерческим предложением.
- Три URL одного продавца не дают три независимых предложения.
- Скрейпер не подтверждает скрытую доставку/налоги или наличие всей партии.
  Для недоступного сайта использовать другие источники, supplier feed или
  датированное КП, привязанное к seller/SKU/количеству; факт ответа не выдумывать.
  Отправка запроса поставщику — отдельная коммуникация с разрешением владельца.
- Нельзя гарантировать все маркетплейсы одним универсальным parser.
  Создаются проверенные адаптеры/whitelists по источникам; unsupported → UNKNOWN.

Google Custom Search JSON API **закрыт для новых клиентов**, существующим
клиентам требуется перейти до 01.01.2027 по официальной документации.
Поэтому новый проект не строится на обещании «получите Google CSE key».
Vertex AI Search по ограниченному набору доменов не объявляется полной
заменой широкого поиска по всем перечисленным DOCX площадкам.

## Предварительная оценка пилота и контроль расходов

Иллюстративный объём, а не обещание реальных затрат: 10 лотов × 10 страниц
= 100 OCR страниц; 60 Brave Search запросов; 100000 AI input + 20000 output
токенов. По приведённым стандартным строкам без скидок это около:
OCR $0.15 + search $0.30 + AI $0.03 + $0.05 = **$0.53**.
Не включены повторные вызовы, thinking сверх указанного output, визуальные
токены сверх input, Storage/Drive, трафик, Firecrawl, местные налоги/FX,
состояние аккаунта/модель и расходы человека. Это пример формулы budget,
не фиксированный тариф полного цикла и не основание автоматически списать.

До платного этапа владелец выбирает processor/model/region и подтверждает
тариф/budget; код резервирует worst-case стоимость по максимальным токенам/
страницам/attempts до вызова, сверяет actual usage после и останавливается
при неопределённом тарифе. Учёт общего расхода Google проекта и других
скриптов остаётся внешним: billing alerts не являются жёстким лимитом.

## Что потребуется от владельца, без секретов в чате

1. Рассмотреть спецификацию и политические уточнения (HIGH/MED ambiguity,
   percent denominator, GO, MED в TOP). Подтвердить выбранный документ по hash,
   если файл (3) отличается от приложенного.
2. Завершить проверки PR #4: официальная зона API, диапазоны/индексация,
   статусы/способы; разрешённый bounded пилот отдельно. Пока не запускать.
3. Подтвердить приватную Drive папку (только её ID), доступ/права и сохранение
   истории; несекретный Google Cloud project ID/region и разрешение на billing.
4. Выбрать Vertex + Document AI + Brave как предложенный набор либо реальные
   альтернативы; установить отдельный лимит затрат/числа запросов. Для
   длинных документов отдельно выбрать временный GCS bucket; Firecrawl опционален.
5. OAuth/ключи вводить только в соответствующей защищённой UI/Secrets/Script
   Properties после отдельного разрешения. Существующий GOSZAKUP_TOKEN не
   экспортировать/пересоздавать; CLASP_AUTH_JSON/APPS_SCRIPT_BACKUP_KEY не менять здесь.
6. Дать несекретный профиль: режим НДС/налогов, поставщик/статус участия,
   планируемое происхождение, логистика/обязательные расходы; официальный
   источник национального режима и реестра/ответственного эксперта.
7. Выбрать 2–10 реальных Lots.id и ожидаемые документы (их номера/версии);
   это данные теста, не API-токены. По возможности включить скан, многопозиционный
   лот, импорт/FX и отрицательный случай. Проверить golden requirements вручную.
8. Указать TTL цен/наличия, окна повторной проверки, пороги цвета маржи и
   уточнения неоднозначных категорий. Новые значения не угадываются.
9. После завершения последующих PR отдельно разрешить публикацию и тестовый
   полный цикл. Масштабирование/автозапуск потребуют отдельного решения по
   реальным результатам, квотам и покрытию, не по fake-тестам.
