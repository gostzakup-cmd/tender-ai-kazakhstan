# Issue #30 — original-PDF-bound technical criterion review matrix

`buildTenderTsCriterionMatrix(input,policy,nowIso,extraction)` reuses the approved original byte/national gate and the existing Document AI OCR candidate transport. Each nonblank OCR line, including headings, numbers and table rows, is retained with its page, character range, verbatim text and optional lexical review flags. Hints (measurement tokens, numeric text, inequality language and tables) are **not** parsed constraints, unit conversions or proven technical requirements. Maximum 15 independently reviewed pages and 500 OCR lines; overflow blocks instead of silently truncating.

`finalizeTenderTsCriterionReview` requires an explicit one-to-one reviewer disposition for every line: REQUIREMENT with criterion ID/critical flag or EXCLUDE with a substantial rationale. Consecutive lines may be grouped into a criterion; non-contiguous joins are rejected. A separate approved trusted registry must bind exact source URL, original PDF SHA-256, lot and announcement, current version, reviewer identity, all original pages and every OCR line, document layout, observed time and identical assignments. An owner/AI-authored JSON boolean alone cannot prove the underlying review. Without external attestation the output remains a draft.

On independently accepted review only, the module produces a `ts.criteria[]` object matching the existing `evaluateTenderResearch` input contract with original-document evidence, criterion text and page references. It **never** supplies the product manufacturer's proof, criterion MATCH assessments, supplier quotes, stock, legal/tax treatment or a GO decision. OCR text and reviewed original page completeness are separate requirements. No live OCR/PDF download, billable call, sheets writes, deployment or trigger change was made. Tests are synthetic, not an actual verified tender.
