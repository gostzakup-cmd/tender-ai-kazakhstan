# Issue #22: текущее доказательство национального режима

Исследование выполнено на `main` после объединённых PR #19–#21 (`b0faeef`).
Наблюдения получены 11 октября 2026 UTC, 12 октября по Asia/Qyzylorda.
Это дата исследования, **не подтверждение временной зоны дат Goszakup API**.
[Досье](national/issue22-observations.json) сохраняет URL, метод чтения,
время окончания локального скачивания, SHA-256 полученных байтов и происхождение
фактов. Полный HTML с ненужными данными заказчиков в репозиторий не добавляется.
Хеш страницы фиксирует наблюдение; он не удостоверяет отсутствующий признак.

## Реальные официальные указания и исключение ЗЦП

1. [Wiki 1311115](https://wiki.goszakup.gov.kz/pages/viewpage.action?pageId=1311115),
   версия **76**, теперь называется «Организация и проведение закупок способом
   "Тендер"». Раздел «Добавление лота в проект объявления» говорит о «Да»
   для соответствующих товаров в состояниях «Заявка», «Отменен», а также «Нет»
   для товаров вне перечня **или** со статусом «Закупка не состоялась».
   Это инструкция создания проекта тендера, не доказательство текущего ЗЦП.
   Статусы этого шага нельзя автоматически сопоставить кодам RefLotsStatus.
2. [Wiki 1311154](https://wiki.goszakup.gov.kz/pages/viewpage.action?pageId=1311154),
   версия **35**, именно участие в ЗЦП. Она описывает ограничение участия
   для поставщика вне реестра КТП и прямо указывает исключение: если по лоту
   ранее проводилась закупка, которая не состоялась, система позволит подать
   заявку поставщику вне реестра. Это объясняет, почему КТРУ сам по себе
   не определяет допуск; не отменяет проверки текущего лота и других ограничений.

Для батарейки прочитана публичная «История»: текущий 88123887-ЗЦП3 связан
с 88123887-ОИ2 / 17741797-1 и 88123887-ЗЦП1 / 17725108-1. В истории
«Аяқталды» относится к **объявлению**, а не является доказательством исхода лота.
Отдельная [карточка предыдущего лота](https://old.goszakup.gov.kz/kz/subpriceoffer/index/17725108/43473903)
HTTP 200 подтверждает 43473903 / 88123887-ЗЦП1, КТРУ 272011.900.000002
и статус «Сатып алу өткен жоқ» («Закупка не состоялась»).
Таким образом, реальная предыдущая неудача найдена, **но текущий признак
88123887-ЗЦП3 всё ещё неизвестен**. Суффикс ЗЦП3 и история не дают PASS_TO_TS.
Даже подтверждённое «Нет» после исключения не означает, что КТРУ никогда
не подпадает под ограничение; причина и актуальное состояние существенны.

История и модальное окно прочитаны только по URL и параметрам, реально
используемым JavaScript открытых страниц, без токенов, cookies или авторизации.
Это чтение открытого UI в рамках исследования, **не установленный контракт
публичного API и не подтверждённое разрешение на автоматический сбор**.
Apps Script scraper таких маршрутов не добавлен. В модальном окне
`data-lot-id=88138120`, а Lots.id — 43544048: UI использует другой контекст.
Статус модального окна «Жарияланды» нельзя подменять статусом реестра лотов.

## Небольшое изменение диагностики

Существующий `inspectTenderNationalEvidence()` теперь дополнительно выводит
`announcementId`, `announcementNumber`, `announcementIdentityVerified`,
`statusId`, исходные начало/окончание/повторные даты, `lotUpdatedRaw` и
`lotIndexedRaw`. Имена отчёта — внутренние; используются только сохранённые
SDL поля Lots и TrdBuy, включая `lastUpdateDate` и `indexDate`.
Плановый и фактический способ остаются отдельными значениями.

`apiContextSha256` сравнивает ограниченные **редактированные** поля отчёта,
включая идентичность, статус, способы, даты, сумму и КТРУ. Это не хеш полного
ответа, не версия закупочного документа и не доказательство национального
режима. `contextFingerprintScope` явно сообщает это ограничение. Повторение
хеша не продлевает свежесть юридического доказательства. Даты остаются
исходными строками, без нового предположения о зоне.

Контракт прежний: 1–3 выбранных ID, одна логическая API-операция, максимум
четыре попытки под общим лимитом; сохранённые реальные кандидаты обязательны.
Единственная разрешённая запись при будущем ручном запуске — счётчик квоты,
не Sheets, формулы, Secrets, cursor или watermark. Все национальные решения
остаются HOLD_NATIONAL; FULL_SCAN_DISABLED и блокировка триггера сохраняются.

## Блокер и следующий разрешённый шаг

Нет подтверждённого источника **текущего per-lot Да/Нет** в прочитанном публичном
HTML и четырёх типах схемы из [отчёта владельца](https://github.com/gostzakup-cmd/tender-ai-kazakhstan/issues/22#issuecomment-6112689479).
186 полей — только эти типы, не вся API. Не найден документированный разрешённый
API-метод получения признака. Доступ из Apps Script к веб-страницам не проверялся.

Владелец может через обычный разрешённый интерфейс портала проверить текущие
объявления/лоты и, **если признак отображается**, сохранить официальный экспорт
или снимок с URL, номером лота и объявления, состоянием, способом и временем
проверки. Перед передачей удалить персональные данные и секреты. Если интерфейс
тоже не показывает признак — запросить у поддержки портала документированный
источник, семантику исключения после неудавшегося ЗЦП и разрешённый метод чтения.
Ни браузерная сессия, ни токен владельца в чат не нужны.

Следующий PR возможен после получения такого материала: сверка свежей
идентичности/статуса/метода/дат с доказательством и его версией, проверка
полноты Plans и исключений. Политику допустимой свежести ещё нужно утвердить;
произвольный TTL здесь не вводится. Подтверждённое ограничение → SKIP;
доказанное отсутствие в текущем контексте → PASS_TO_TS; конфликт, устаревание
или отсутствие доказательства → HOLD_NATIONAL. К поиску ТС/поставщиков и
расчёту реальной маржи ≥20% можно переходить лишь после этого допуска.
