# Текущее состояние MVP

Обновлено 2026-10-09. Приложение — Apps Script + Sheets, без сервера и Python.

Владелец подтвердил установленную версию, setup, соединение, схему и две
страницы API. В реальном inspectTenderStage2Evidence сверены пять пар
портальных/API ID, Lots.amount/count первого товара и строки дат.
Отчёты, происхождение и ограничения: [STAGE2_READINESS.md](STAGE2_READINESS.md).

Подготовлены настройка пяти основных листов, V3 адаптер, дедупликация,
обновления, проверки/диагностика, безопасная ручная публикация Actions с
backup и повторным чтением, а также новый [ограниченный пилот](BOUNDED_PILOT.md).
В пилоте четыре фильтрованных потока, дедупликация Lots.id, отдельные
события публикации/смены статуса, fallback планов по pointList, карантин,
жёсткие лимиты и проверка pageInfo/count. Новый пилот в Google не опубликован.

Блокеры:

1. Временная зона строк API без offset не подтверждена официально.
   Равенство строк с порталом и Asia/Almaty манифеста её не устанавливают.
2. Пустые Plans у 11/20 опубликованных записей: тип неизвестен; требуется
   реальная проверка получения планов по явным ID и причины отсутствия связи.
3. Полнота набора статусов новых заявок и применимость по всем способам
   не доказаны. Справочник всех 37 получен; два начальных кода консервативны.
4. Семантика диапазонов, lastUpdateDate/indexDate и распространение
   изменений связей/удаления не доказаны. Пилот не обнаружит невыданный ID
   без независимого ожидаемого набора; двух страниц недостаточно.
5. Production-курсор/очереди/watermark/архивирование и безопасный суточный
   охват 32,4 млн записей ещё не реализованы. Ежедневный полный scan превышает
   стандартные URL Fetch квоты; новый код блокирует sync/trigger даже с proof.
6. Реальные квоты, задержки индексации и покрытие надо измерить ограниченным
   пилотом после разрешения владельца; его локальные тесты этого не заменяют.

CONNECT 403 не является ошибкой API-токена; официальная документация
доступна. Ни Google Secrets, ни Apps Script в этой работе не менялись.

Дальше: рассмотрение PR → официальный ответ по зоне/фильтрам → отдельно
разрешённая публикация → настройка/новая диагностика → отдельно разрешённый
ограниченный пилот → анализ покрытия → разработка ежедневного режима.
