# Загрузка в существующий Apps Script без копирования файлов

Целевой Script ID:
`1_UmAJ7xfIks7b2Q_PjDt_xUoEzovUIh5V5e_leuiJW2O9MGA9maQGL-y`.

**Текущий результат: загрузка не выполнена.** 2026-10-08 в облачной среде
установлен и запущен официальный `@google/clasp` 3.4.1. Попытка clone
этого Script ID завершилась `No credentials found`. OAuth-сессии clasp
нет; GOOGLE_APPLICATION_CREDENTIALS указывает на пустой JSON без токенов.
GET Apps Script API остановился на `403 CONNECT` прокси до ответа Google.
Наличие и содержимое файлов удалённого проекта пока не проверены.
`GOSZAKUP_TOKEN` из Script Properties не читался и не изменялся.

Подготовлен [помощник загрузки](../tools/apps-script-upload.cjs). Он
использует clasp как клиент Google Apps Script API; сервер приложения
по-прежнему не нужен. Помощник не вызывает функции Apps Script, не читает
Script Properties, не создаёт deployments и триггеры.

## Авторизация и загрузка на вашем компьютере

Команды ниже для macOS, Linux или Windows через WSL. Нужен Node.js 20+
и доступ к репозиторию с текущими файлами. Этот способ не требует
передавать Google OAuth credentials в облачную среду или чат.

Используйте подготовленный архив текущих файлов или скачайте рабочую
копию из этой среды. Изменения пока не отправлены в GitHub: обычный
clone ветки main не гарантирует наличие помощника и новых `.gs`.

1. Под аккаунтом с правом редактировать привязанную таблицу и её проект
   откройте https://script.google.com/home/usersettings и включите
   **Google Apps Script API**. Убедитесь, что открывается ваш проект:
   https://script.google.com/home/projects/1_UmAJ7xfIks7b2Q_PjDt_xUoEzovUIh5V5e_leuiJW2O9MGA9maQGL-y/edit
2. Установите clasp и войдите в этот же аккаунт:

   ```sh
   npm install -g @google/clasp@3.4.1
   clasp --version
   clasp login
   ```

   Браузер запросит Google OAuth-разрешения. Для чтения/записи исходников
   требуется `https://www.googleapis.com/auth/script.projects`; стандартный
   клиент clasp запрашивает дополнительные права для других своих команд.
   Это отдельная авторизация Google, не токен Goszakup. Не используйте
   `--use-project-scopes` для этой загрузки: runtime scopes приложения
   не заменяют script.projects. Файл `~/.clasprc.json` содержит секреты,
   его не коммитьте, не отправляйте в чат и не кладите в папку загрузки.
3. Из корня локального репозитория запустите подготовку. Выберите новую
   папку вне репозитория; приведённое имя не должно уже существовать:

   ```sh
   node tools/apps-script-upload.cjs prepare "$HOME/tender-upload-review"
   ```

   Будет прочитан весь удалённый проект. Результат `PREPARED_ONLY` ещё
   не означает загрузку. В папке появятся:

   - `backup/` — полная исходная копия проекта;
   - `stage/` — существующие файлы плюс восемь `.gs` MVP и обновлённый манифест;
   - `plan.json` — имена и SHA-256 без содержимого исходников;
   - `REVIEW.md` — что проверить перед отправкой.

4. Сравните `backup/` и `stage/`, особенно файлы с совпадающими именами и
   `appsscript.json`. Посторонние JS/HTML остаются неизменными. Проверьте
   отсутствие конфликтующих глобальных функций/переменных, особенно
   второго `onOpen`, в сохранённом коде. Если конфликты есть, остановитесь
   и разберите их до отправки; помощник не решает смысловые конфликты.

   Обновление манифеста сохраняет существующие dependencies, явные
   oauthScopes и дополнительные настройки; добавляет обязательные права
   MVP и его V8/часовой пояс. Если старые права определялись автоматически
   (oauthScopes отсутствовал), проверьте права старого кода в редакторе
   **Обзор → Области действия OAuth проекта** и добавьте их в
   `stage/appsscript.json`. Автоматически угадывать их помощник не будет.

5. После проверки отправьте подготовленную версию:

   ```sh
   node tools/apps-script-upload.cjs push "$HOME/tender-upload-review" --reviewed
   ```

   Помощник снова читает удалённый проект. Если он изменился после
   подготовки, загрузка останавливается с `REMOTE_CHANGED` — создайте
   новую папку/копию и повторите проверку. Не редактируйте проект другим
   клиентом во время загрузки: API не предоставляет атомарной проверки
   версии между чтением и записью.

   `clasp push --force` отправляет **весь подготовленный набор**, включая
   сохранённые посторонние файлы; force здесь заменяет проверенный
   манифест. Не запускайте push из корня репозитория: непереданные файлы
   могут исчезнуть, потому что projects.updateContent заменяет всё
   содержимое проекта, а не добавляет отдельные файлы.

6. Успех подтверждён только сообщением **`UPLOAD_VERIFIED`**. Оно появляется
   после нового clone и сравнения имён, типов и SHA-256 всех файлов с
   stage. Для манифеста сравнивается JSON без различий форматирования.
   Файл `verified.json` хранит результат сверки; резервную копию сохраните.
   Если push прошёл, а проверка не прошла, результат остаётся
   **непроверенным**: не повторяйте загрузку вслепую.

7. Откройте Apps Script и проверьте файлы Config, Sheets, Api, V3, Sync,
   Diagnostics, SelfTests и appsscript.json. Запустите `setupTenderMvp`,
   `runTenderSelfTests`, затем `testGoszakupV3Connection`. Имеющийся
   `GOSZAKUP_TOKEN` в Script Properties не нужно вводить повторно.
   Дальнейшие настройки API и ежедневного запуска описаны в README.md.

## Если загрузку должен выполнить именно агент в облачной среде

Локальный `clasp login` не переносит авторизацию сюда. Нужна OAuth-сессия
пользователя с правами на проект **в этой среде**, предоставленная через
защищённое хранилище/терминал, а не сообщением чата. Здесь нет доступного
Google Apps Script connector и нет подключённой пользовательской сессии.

В черновике среды сохранены дополнительные домены:
`script.googleapis.com`, `oauth2.googleapis.com`, `accounts.google.com`,
`www.googleapis.com`, `developers.google.com`, `script.google.com`.
Сохранены также воспроизводимая установка clasp и инструкции старта.
Предыдущие домены Goszakup сохранены. В настройках среды просмотрите,
сохраните изменения и опубликуйте среду; сохранение черновика само по
себе не применяет сетевые изменения и не создаёт OAuth-сессию.

Если вам доступен защищённый терминал этой среды, после применения сети:

```sh
/tmp/tender-clasp/node_modules/.bin/clasp login --no-localhost
```

Откройте показанную OAuth-ссылку в браузере; после согласия перенаправление
на localhost может показать недоступную страницу. Скопируйте полный URL
из адресной строки **в запрос терминала clasp**, а не в чат: URL содержит
одноразовый код авторизации. Не включайте запись секретов в журналы.
В clasp 3.4.1 этот сценарий проверен по официальному исходному коду;
реальная авторизация здесь ещё не выполнена.

Для защищённого альтернативного auth-файла clasp поддерживает
`clasp_config_auth` или глобальный `--auth`; файл должен оставаться
вне репозитория и резервных копий исходников. Сервисный аккаунт и токен
Goszakup не заменяют пользовательский OAuth-доступ к данному Apps Script.
При отсутствии защищённого способа входа используйте локальную процедуру
выше, без передачи credentials агенту.

Если организация запрещает встроенный OAuth-клиент clasp, настройте свой
Google Cloud проект: включите Apps Script API, настройте OAuth consent
screen, добавьте нужного test user при режиме Testing, создайте OAuth
client типа Desktop app и войдите через `clasp login --creds <file>`.
Файл client credentials храните вне репозитория. Требования дополнительных
API и областей действия зависят от используемых команд clasp.
Официальное руководство: https://github.com/google/clasp#authorization
и https://developers.google.com/apps-script/api/how-tos/manage-projects .

## Проверки помощника

```sh
node --test tests/core.test.cjs tests/upload.test.cjs
```

63 теста MVP + 8 тестов загрузчика: сохраняются JS/HTML и зависимости,
права, проверяется отдельная резервная копия, блокируются непроверенная
отправка и конкурентное изменение, обнаруживается пропавший файл после
push. Это искусственный clasp/API в локальных тестах, не подтверждение
загрузки в Google.
