# Issue #18, часть 2: ограниченная подготовка доказательств

`inspectTenderNationalEvidence()` — новая ручная диагностика. Она готовит
проверяемые данные трёх лотов, но **не** определяет национальный режим.
Исследование официальных источников и неизвестные значения — в
[PR #19](https://github.com/gostzakup-cmd/tender-ai-kazakhstan/pull/19).
Этот PR основан на `main` `4010523` и не требует предварительной публикации PR #19.

## Контракт

- По умолчанию только ID из Issue: `43543910`, `43544048`, `43544131`.
  Через аргумент можно явно передать 1–3 уникальных положительных GraphQL Int ID.
  Нет поиска по названию, случайной выборки, пагинации или полного обхода.
- До запроса нужны существующие технические листы и соответствующие строки
  `PILOT_LOTS` с `ELIGIBLE_GOODS`, валидным сохранённым ID, товарным/активным
  признаком и бюджетом каждого лота ≤10 000 000 KZT. Неподтверждённые кандидаты
  не запрашиваются и сохраняют неизвестный результат.
- Один логический GraphQL-запрос к существующему официальному
  `https://ows.goszakup.gov.kz/v3/graphql`, максимум четыре HTTP-попытки,
  включая retries. Используется существующая авторизация, TLS-проверка и запрет
  redirect; Bearer не отправляется на портал или «Әділет».
- Общий с пилотом лимит — 200 попыток за скользящие 24 часа в
  `TENDER_PILOT_QUOTA`; блокировка скрипта защищает резервирование. Любая попытка,
  включая 403/503, заранее учитывается. Повреждённый/исчерпанный счётчик запрещает
  запрос. Лимит проверяет этот пробник и существующий пилот, но не старый
  `inspectTenderNationalKtru()` и другие функции без этого счётчика.
- Проверка времени до попытки и после ответа — 30 секунд. Apps Script не позволяет
  прервать уже выполняющийся UrlFetch; поздний ответ не подтверждает кандидата.
  Длинный Retry-After переносится на последующий ручной запуск, не обходится.
- Проверяются идентификаторы всего ответа до принятия данных отдельных лотов.
  Чужой/повторный ID или неверная форма ответа запрещает подтверждение пакета.
  Не возвращённый ID получает `LOT_NOT_RETURNED`, а не доказательство удаления.
- По свежим данным проверяются `isDeleted=0`, прямые `Lots.amount/count`,
  точное соответствие `trdBuyId` ↔ `TrdBuy.id`, плановый `refTradeMethodsId`
  и фактический `refBuyTradeMethodsId` раздельно, полное уникальное покрытие
  `pointList` → `Plans.id`, товарный `refSubjectTypeId=1` и валидные
  `refEnstruCode`. Максимум 30 пунктов одного лота; больший/неполный состав
  удерживается, дополнительных запросов Plans нет.
- Классификация `ELIGIBLE_GOODS` возможна только с действующим ранее полученным
  fingerprint конфигурации, проверками существующего нормализатора, активным
  настроенным кодом статуса, известными публикацией/началом/окончанием и
  открытым сейчас интервалом. Неустановленная зона, изменённая конфигурация,
  истёкший срок или неизвестные значения дают `UNVERIFIED`. Классификация не
  подтверждает полноту справочника статусов или юридический допуск поставщика.

Запрашиваются только поля сохранённых официальных SDL:
[Lots](v3-schema/lots.graphql), [PlnPoint](v3-schema/plnpoint.graphql),
[TrdBuy](v3-schema/trdbuy.graphql),
[фильтр ID](v3-schema/lotsfiltersinput.graphql). Неподтверждённого поля изъятия
нет; пользовательская remapping-конфигурация и другой endpoint не принимаются.
Текущие реальные ответы этих трёх лотов в этом PR **не получены**.

## Национальный режим и побочные эффекты

Каждый лот возвращает `nationalRegime: UNVERIFIED`, `decision: HOLD_NATIONAL`,
`nationalProofUrl: null`, `nationalProofObservedAt: null`,
`sourceValidity: NO_AUTHORITATIVE_LOT_PROOF`, `methodScopeVerified: false`.
Ни КТРУ, ни разные способы, ни полные Plans не дают `SKIP` / `PASS_TO_TS` / `GO`.
Отдельно показываются дата наблюдения API, endpoint, способы, состав и причины
неподтверждённой классификации. API endpoint — источник данных, не proof URL
национального режима. Показанная дата наблюдения не доказывает свежесть правил.

Режим `API_READ_ONLY_QUOTA_ACCOUNTED` означает чтение данных API и Sheets с
**единственной записью служебного счётчика `TENDER_PILOT_QUOTA`**. Это не функция
без любых побочных эффектов. Другие Properties, включая токен, fingerprint и
курсоры, не меняются; G:J, формулы K, заметки L и все остальные Sheets сохраняются.
Нет записи LOGS, новых листов, триггеров, watermark, вызовов sync/pilot/TS или
выдачи `mvpReady=true`. Возвращаются только ограниченные значения и фиксированные
коды ошибок; токен редактируется до сокращения строк и логирования.

## Установка и ручная проверка владельцем — позже

В этом PR **не запускались** Google-функции, публикация или реальная диагностика.
Manifest, scopes, Secrets и workflow публикации не изменены.

После отдельного разрешения владельца на публикацию:

1. Выполнить обычный ручной `prepare`, проверить резервную копию и план изменения
   `Pilot.gs`; затем отдельно разрешённый `publish` с повторным чтением проекта.
2. Сохранить существующие настройки и токен. Не менять timezone/status/URL ради
   прохождения проверки и не создавать fingerprint вручную. Функция диагностирует
   отсутствие proof, не исправляет его и не ослабляет блокировки.
3. Отдельно разрешённый ручной запуск `inspectTenderNationalEvidence` в редакторе
   использует три ID по умолчанию. Полный sync, pilot и daily trigger не нужны.
   Если ID нет среди подтверждённых сохранённых кандидатов, результат остаётся
   неизвестным без запроса; не добавлять искусственные строки в `PILOT_LOTS`.
4. Проверить отчёт: `requests`, `issue`, `apiResponseValidated`, `dataIssues` и
   каждую строку отдельно. Отчёт уже редактирует токен; перед пересылкой ещё
   проверить отсутствие частных данных. Отсутствие ответа не означает «Нет».
5. Для следующего PR получить разрешённый официальный lot-level источник отметки
   или полный актуальный набор правовых доказательств с версиями и исключениями.
   Тогда отдельно реализовать и проверить `SKIP` / `PASS_TO_TS` / `HOLD_NATIONAL`.
