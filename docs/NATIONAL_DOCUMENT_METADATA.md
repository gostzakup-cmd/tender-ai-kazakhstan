# Issue #22: реальные документы и следующий шаг проверки

Этот небольшой PR основан на `main` `b0faeef` и не требует объединения
[PR #23](https://github.com/gostzakup-cmd/tender-ai-kazakhstan/pull/23).
Проверяется только происхождение документов и их метаданные. Национальный
режим трёх лотов остаётся **UNVERIFIED / HOLD_NATIONAL**.

## Что получено в действительности

[Досье наблюдений](national/issue22-document-observations.json) содержит реальные
URL, UTC-время окончания скачивания и SHA-256 ответов. Запросы были открытыми
GET без токенов/cookies; Google-функции и Apps Script не запускались.

- Официальные страницы [Lots](https://ows.goszakup.gov.kz/help/v3/schema/lots.doc.html)
  и [FileLots](https://ows.goszakup.gov.kz/help/v3/schema/filelots.doc.html) доступны
  (200). `Lots.Files: [FileLots]` — документированный путь к документам лота.
  Все восемь полей FileLots сохранены в [SDL](v3-schema/filelots.graphql).
  `objectId` описан только как «ID объекта», а `indexDate` — дата индексации;
  их значение как Lots.id / Plans.id / версии документа **не подтверждено**.
- Карточка [43543910](https://old.goszakup.gov.kz/kz/subpriceoffer/index/17757379/43543910),
  ранее ответившая 503, теперь вернула 200. В ней лот 88198152-ЗЦП1,
  статус приёма предложений, начало `2026-10-09 16:30:00` и окончание
  `2026-10-13 16:30:00`. Это строки портала, не новая проверка IANA timezone.
  Национального «Да/Нет» в прочитанном HTML нет.
- Текущий `v3bl.goszakup.gov.kz/ru/announce/index/17757453` перенаправил
  на `/ru/user/login`. HTTP 200 страницы входа не подтверждает чтение объявления.
  На этом граница доступа остановлена.
- На [вкладке документов](https://old.goszakup.gov.kz/kz/announce/index/17757453?tab=documents)
  старого портала кнопка ТС вызывает реально указанный публичный JavaScript
  `actionModalShowFiles(17757453,125)`. Скрипт использует GET для списка файлов;
  маршрут взят из скрипта, а не угадан. Этот UI-маршрут не объявляется
  документированным API или разрешённым контрактом автоматического сбора.
- [Список ТС](https://old.goszakup.gov.kz/kz/announce/actionAjaxModalShowFiles/17757453/125)
  явно связывает 88138120-ЗЦП1 с `techspec_17757453_43544048.pdf`.
  [Оригинальный PDF](https://v3bl.goszakup.gov.kz/files/download_file/316693537/227389564/)
  доступен без авторизации: 200, PDF, 27 648 байт, две страницы. Внутри указаны
  объявление 17757453-1 и лот 88138120-ЗЦП1. Это проверяемая привязка
  публичной строки, имени файла и заголовков PDF к известному лоту.

PDF прочитан локальным `pdftotext` только для проверки идентичности и наличия
признака национального режима. Полный текст с ненужными контактными данными
не добавлен в Git. Это не реализация анализа ТС, соответствия товара или AI.
Криптографическая подпись и актуальная версия документа не проверены;
сегменты URL скачивания не объявляются значениями `FileLots.id/objectId`.
**Отсутствие национального признака в PDF не означает отсутствие ограничения.**

В таблице документации имеются «Иә/Жоқ» для других строк, в том числе ТС.
Они не подписаны «Изъятие из национального режима» и не являются доказательством
национального допуска. Ни любой встреченный «Нет», ни КТРУ, ни полученный PDF
не дают PASS_TO_TS. Прежнее исключение после неудавшегося ЗЦП требует
подтверждения в контексте текущего лота, как описано в PR #23.

### Новое доказательство из скриншота владельца

Затем владелец предоставил ссылку
`https://v3bl.goszakup.gov.kz/ru/announce/index/17745688` и скриншот браузера
с адресом `zakup.gov.kz/cabinet/announcement/17745688`. На нём во вкладке
«Лоты» видна строка «Шина», сумма 200 000 KZT, статус «Опубликован
(прием ценовых предложений)» и явная колонка **«Изъятие из национального
режима» со значением «Да»**. Это положительное доказательство того, что новый
интерфейс действительно показывает признак. Номер лота и Lots.id в кадре
не видны из-за горизонтальной прокрутки; момент проверки в UTC не установлен.
Скриншот с персональными данными не помещён в Git и его хеш не придуман.

В реально подключённом публичном модуле `Announcement-Bltue7ul.js` найден
рендерер этой колонки: ключ перевода `registry.nationalWithdrawal`,
проверка наличия `lot.national_withdrawn` и выбор
`row.__planPoint.national_withdrawn ?? lot.national_withdrawn` для «Да/Нет».
`__planPoint` создаётся из `lot_points[].plan_point`. Таким образом, важен
контекст каждой отображаемой строки, особенно если лот объединяет пункты.
Это **наблюдаемые ключи frontend**, не поля подтверждённой схемы OWS V3.
`national_withdrawn` не добавлен в GraphQL Lots; форма, тип и семантика
реального API-ответа этого нового интерфейса пока не проверены.

Внешнее чтение переданной ссылки v3bl опять ведёт к login. Наличие доступного
JS не даёт доступ к авторизованным данным. Скриншот не переносится на лоты
43543910/43544048/43544131: другое объявление и неизвестен устойчивый ID
показанного лота. Для этой строки следующий шаг — в обычном интерфейсе
прокрутить таблицу влево и записать номер лота, затем связать его с Lots.id
и актуальным состоянием. После подтверждения этой связи ограниченный лот
можно исключить (`SKIP`); до связи никакой записи по предполагаемому ID нет.

## Небольшое изменение Apps Script

Добавлена ручная функция **`inspectTenderNationalDocumentEvidence()`**.
Она вызывает прежний ограниченный пробник с опцией метаданных документов:

```javascript
inspectTenderNationalEvidence(undefined, true);
// Либо один конкретный существующий подтверждённый кандидат:
inspectTenderNationalEvidence([43544048], true);
```

По умолчанию `inspectTenderNationalEvidence()` сохраняет прежнюю выборку полей
без Files и прежний формат лога. Новый режим добавляет к **тому же** GraphQL
запросу только `Files.id/objectId/originalName/nameRu/nameKz/indexDate/systemId`.
`filePath` не запрашивается и не отражается в отчёте, чтобы не публиковать
возможные подписанные URL. Bearer отправляется только в официальный OWS.
Нет запросов к UI, PDF, CMS или внешнему AI из Apps Script.

Результат каждого возвращённого лота содержит `documentMetadata`:

- `parentLotId`, `sourcePath: Lots.Files`, проверенные по форме метаданные;
- `METADATA_ONLY`, `EMPTY_API_RELATION` либо `UNVERIFIED` с фиксированной причиной;
- всегда `objectIdSemanticsVerified: false`, `currentVersionVerified: false`,
  `nationalProof: false`. При отсутствии лота метаданные не подтверждаются.

До 10 файлов на один лот; превышение не обрезается до ложного «полного списка»,
а удерживает весь список неподтверждённым. Дубликаты ID, неправильные типы,
отсутствующие ключи и строки свыше 512 символов тоже удерживаются.
Это **предел после ответа**: у `Lots.Files` нет подтверждённых параметров limit
или пагинации, и такой параметр не придуман. Размер ответа также ограничен
платформой UrlFetch; слишком большой ответ может завершиться безопасной ошибкой.
Пустое Files не доказывает отсутствие документов на портале.

Новый лог выдаётся частями `NATIONAL_DOCUMENT_JSON_PART_1`, `_2`, … по
4000 символов после удаления секретов. Для просмотра полного JSON объединить
только содержимое частей по порядку, без префиксов и временных меток.

Сохраняются 1–3 выбранных реальных кандидата из PILOT_LOTS, общий счётчик квоты,
максимум четыре попытки, блокировка скрипта и предыдущие проверки данных.
При будущем запуске меняется только счётчик квоты. Sheets, формулы, Secrets,
manifest/scopes, watermark и workflow публикации не меняются. FULL_SCAN_DISABLED
и запрет триггера сохраняются. Все национальные решения — HOLD_NATIONAL.

## Что нужно от владельца

Публикация этого PR и запуск новой диагностики **сейчас не выполнены**.
После отдельного разрешения и обычного prepare/review/publish можно один раз
запустить новую функцию с уже имеющимся токеном. Отчёт покажет реальную
API-идентичность файлов; пока такого ответа FileLots здесь нет. Не менять
настройки, не создавать фиктивные строки кандидатов и не включать sync/pilot.

Для национального допуска нужен текущий явный признак с идентичностью лота,
объявлением, состоянием, способом, временем и версией доказательства. Если он
виден в законном интерфейсе владельца, сохранить официальный экспорт/снимок
без секретов. Если не виден — отправить подготовленный ниже запрос через обычный
официальный канал поддержки. **Этот PR не отправляет обращение за владельца.**

> Просим указать официальный разрешённый источник текущего признака
> «Изъятие из национального режима — Да/Нет» для следующих опубликованных
> товарных лотов ЗЦП: Lots.id 43543910 / 88198152-ЗЦП1 / 17757379-1;
> 43544048 / 88138120-ЗЦП1 / 17757453-1;
> 43544131 / 88123887-ЗЦП3 / 17757463-1.
> В открытых карточках и документации API V3 этот явный признак не найден.
> Нужен документированный API-метод либо точное расположение признака
> в разрешённом интерфейсе, его привязка к Lots.id, версия и дата обновления.
> Просим уточнить исключение для ранее неудавшегося ЗЦП: история третьего лота
> связывает его с 43473903 / 88123887-ЗЦП1 / 17725108-1 со статусом
> «Закупка не состоялась». Каким доказательством подтверждается применение
> исключения именно к текущему объявлению и лоту? Допускается ли автоматическое
> чтение указанного источника из Apps Script и при каких ограничениях?
> Также просим уточнить связь идентификаторов нового интерфейса
> zakup.gov.kz/cabinet/announcement/17745515 с реестром OWS V3 и расположение
> текущего признака национального режима в новом интерфейсе.
> В интерфейсе объявления 17745688 владелец видит «Да» для строки «Шина».
> В публичном frontend наблюдается national_withdrawn на лоте и пункте плана;
> просим подтвердить официальный API-контракт этого признака, его тип,
> контекст/наследование и сопоставление ID с OWS V3. Это наблюдение JS,
> а не утверждение о поле GraphQL Lots.
> Токены и учётные данные в обращение не включаем.

После ответа возможен отдельный адаптер на подтверждённом источнике. До этого
не вводятся произвольный срок свежести, предположительный классификатор или
коммерческий допуск. Полученный PDF — материал для следующего этапа только после
подтверждённого PASS_TO_TS и проверки его действующей версии.
