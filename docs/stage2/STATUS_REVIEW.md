# Разбор всех 37 статусов

Источник кодов: [полный реальный отчёт владельца](status-reference.user.json).
Получен 2026-10-09; 37 уникальных ID, 36 уникальных code. ID 295 и 300
имеют одинаковый code GenerateProjectPPD: не объединять записи справочника.
Ошибки написания кодов сохранены как в API. Это справочник состояний,
а не API-проверка права конкретного поставщика подать заявку.

## Новые первоначальные заявки

Консервативный кандидат настройки для новых заявок в обследованных
процедурах: `["PublishedBidAccept","PublishedOfferAccept"]`.
Проверка интервала startDate/endDate обязательна. Кандидат не является
доказательством полного покрытия всех специальных способов и правил
участия; в Script Properties пока не записан.

Официальные инструкции ЗЦП, ОК и аукциона требуют статус приёма.
Из одного источника также требуется приглашение. PublishedBidAdditional
не включается в список новых первоначальных заявок: это дополнения;
нельзя обещать участие новому поставщику по этому коду.
Если нужны дополнения уже поданных заявок, это отдельная семантика
ACTIVE_LOTS, с repeatStartDate/repeatEndDate и проверкой применимости.

## Основания из официальных инструкций

- [ЗЦП](https://wiki.goszakup.gov.kz/pages/viewpage.action?pageId=1311154):
  «Статус объявления должен быть “Опубликовано (прием ценовых предложений)”».
- [ОК](https://wiki.goszakup.gov.kz/pages/viewpage.action?pageId=1311120):
  создание заявки доступно после начала приёма при статусе приёма заявок.
  «После завершения приема заявок если проверки не были завершены по всем
  заявкам Система переведет статус закупки на “Опубликовано (проверка заявок)”».
- [Аукцион](https://wiki.goszakup.gov.kz/pages/viewpage.action?pageId=1311047):
  содержит то же правило для проверки заявок и отдельно описывает ожидание
  и проведение торгов **после** окончания приёма заявок.
- [Из одного источника](https://wiki.goszakup.gov.kz/pages/viewpage.action?pageId=1311082):
  возможность подачи появляется после уведомления с приглашением.

Инструкции описывают состояния объявлений/действия поставщика. Их нельзя
использовать для угадывания числового refBuyStatusId; реальные коды лотов
сверяются с RefLotsStatus и ответами конкретных опубликованных Lots.
