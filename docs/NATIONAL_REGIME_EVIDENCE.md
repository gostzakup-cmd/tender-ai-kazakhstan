# Issue #18: официальные источники национального режима

Первая часть задачи: исследование источников и тесты существующей диагностики.
Проверено 10.10.2026 (Asia/Qyzylorda), относительно `main` `4010523`.
Автоматический классификатор **не реализован**: текущих доказательств для
конкретных лотов нет. Этот документ и JSON не являются списком допуска.

## Что именно фильтруем

Юридический «национальный режим» означает равные условия допуска, а ограничение
возникает при **изъятии из национального режима**. Поэтому запрошенные решения
относятся к применимому изъятию, а не к наличию национального режима вообще:

| Доказательство по конкретному актуальному лоту | Следующее действие |
| --- | --- |
| Применимое изъятие авторитетно подтверждено («Да») | `SKIP` |
| Авторитетно подтверждено отсутствие применимого изъятия («Нет») | `PASS_TO_TS` |
| Отсутствующее, устаревшее, неполное или противоречивое доказательство | `HOLD_NATIONAL` |

`SKIP` — выбранная владельцем стратегия отбора, а не юридическое заключение,
что участвовать не может ни один казахстанский производитель. `PASS_TO_TS`
разрешает только дальнейшую работу с ТС; это не `GO`, не заявка и не обещание
допуска. Сертификаты и товарные знаки учитываются далее как отдельные риски;
их наличие само по себе не доказывает изъятие.

## Портал и схема OWS: подтверждённое и неизвестное

Опубликованные снимки [Lots](v3-schema/lots.graphql) и
[PlnPoint](v3-schema/plnpoint.graphql), проверенные ранее 08.10.2026,
документируют `Lots.id`, `pointList`, `Plans`, `refTradeMethodsId` (плановый),
`refBuyTradeMethodsId` (фактический), `Plans.id`, `refSubjectTypeId`,
`refEnstruCode` (код КТРУ). Они **не документируют поле итогового изъятия**.
`isLightIndustry`, `enstruList`, `disablePersonId` не заменяют этот итог.
Это утверждение о сохранённых снимках, не доказательство отсутствия поля во
всех интерфейсах/будущих версиях OWS. Новые имена полей не добавлены.

проверки документации и условий портала; обход входа, CAPTCHA или блокировок

## Ограничения существующих функций и сохранность данных

`refreshTenderNationalGate()` сохраняет пользовательские G:J, формулы K и
заметки L; существующие строки не удаляет. Формула K проверяет значение G и
непустоту H:I:J, **не** авторитетность URL, актуальность, версию, противоречия
или охват всех пунктов плана. Поэтому K — ручная очередь, а не готовое
автоматическое доказательство. Её нельзя использовать для запуска ТС, закупки
или `GO` до независимого проверенного шлюза. В этом PR формулы не меняются.

`inspectTenderNationalKtru()` читает максимум три активных товара из сохранённого
пилота и сверяет `pointList` с `Plans`. Выбирает первые ID, а не обязательно
три ID Issue #18. Даже полный КТРУ даёт только `UNVERIFIED`. Функция не проверяет
свежие статус/сумму/удаление/способ и не имеет общего суточного бюджета проб;
HTTP transport ограничивает один запрос четырьмя попытками. Это ограничения
текущего пробника, которые следующий PR должен закрыть до нового пилота.

Все `.gs`, manifest, инструмент публикации, секреты и существующие Google Sheets
в этом PR неизменны. Полный обход и daily trigger по-прежнему блокирует
`assertApiReady_()` → `FULL_SCAN_DISABLED`. Никакие Google-функции не запускались.

## Следующие небольшие PR и критерии приёмки

1. **Этот PR:** проверяемые официальные источники, неизвестные значения,
   тесты сохранности ручных доказательств и отказов текущей диагностики.
2. **Bounded read-only verifier:** явно выбранные максимум три ID; свежие
   подтверждённые API-поля товара, бюджета каждого лота ≤10 млн KZT,
   удаления/статуса/фактического способа; полное покрытие Plans; лимит каждой
   HTTP-попытки/суток/времени; отсутствие записей в Sheets/Properties/триггеры.
   Общий лимит нужен заранее: отдельная, явно разрешённая запись квотного
   счётчика либо использование существующего счётчика через согласованный
   контракт; нельзя называть пробник строго read-only, если он меняет счётчик.
   Выводить публичный proof URL, дату наблюдения, годность источника, способ
   и причину; до подтверждения источника — только `UNVERIFIED`.
3. **Адаптер доказательств:** только после получения допустимого реального
   источника отметки лота/полного набора правовых списков. Проверить `Lots.id`,
   объявление, актуальную версию, точную цитату «Да/Нет», полный состав и
   применимость на дату закупки. Сохранять версию/хеш и разрешённый срок
   свежести; неожиданный HTML/схема, отмена/замена, смешанные коды, исключения,
   неполный список, недоступный источник → `HOLD_NATIONAL`. Один снимок
   пользовательского текста или КТРУ сам по себе не авторитетное доказательство.
4. **Чистый классификатор и отдельный журнал:** `SKIP` / `PASS_TO_TS` /
   `HOLD_NATIONAL` по проверенным доказательствам; журнал с `Lots.id`,
   причиной и историей, без перезаписи G:J/K. Никакого `GO`. Тесты истинных
   «Да»/«Нет», неизвестного, противоречий, устаревания, отмен, исключений,
   смешанных КТРУ, дублей, HTTP/квот, повторного запуска и отсутствия побочных
   эффектов. Применение к трём реальным лотам — только отдельный разрешённый запуск.
5. **После доказанного шлюза:** только `PASS_TO_TS` → оригинальная ТС →
   соответствующая точная модель → по возможности ≥3 независимых поставщика
   РК/РФ/КНР → полная доставленная себестоимость, конкуренция, маржа ≥20%
   и `GO`/`REVIEW`/`NO-GO`. Неподтверждённые цены/наличие отдельно, бюджет
   не гарантированная выручка; разрешение национального шлюза не гарантирует GO.

От владельца для следующего этапа нужны публичные официальные материалы
портала/актуальные кодовые перечни либо очищенные ответы и снимки отметки
именно трёх лотов с ID, URL, датой и версией. Никакие токены в чат не нужны.
Новый read-only пробник будет подготовлен для безопасного запуска в Apps Script,
если облачный доступ остаётся закрытым. Отдельно согласуются свежесть доказательства
и бюджет запросов; отсутствие ответа не означает разрешение.

## Проверки, публикация и откат

Проверки выполняются локально без Google/API запросов:

```sh
node --test tests/core.test.cjs tests/upload.test.cjs tests/actions.test.cjs
git diff --check
```

Существующий workflow `PR tests (read-only)` запускает те же три набора;
не обращается к Apps Script и не получает Secrets публикации. Новые сценарии
используют явно синтетические ответы, не подменяют реальные доказательства.
Результат текущего запуска и GitHub CI приводится в PR.

Этот PR **не требует публикации Apps Script**. Откат — revert только документации
и тестов; миграций, удаления листов или восстановления пользовательских данных
не требуется. Следующие runtime PR публикуются лишь отдельно разрешённым
ручным `prepare` → проверка владельцем → `publish` с резервной копией и
повторным чтением; PR/CI не должны запускать сбор.
